# Prompt 模板库组织设计

## 目标

在 Prompt 数量从十几个增长到数百个时，用户仍能快速完成“找到模板、补全内容、粘贴”，同时保留来源、使用历史和用户自己的整理方式。

本设计采用“一条主分类、多枚标签、独立状态”的两层结构，不引入无限嵌套文件夹。

## 官方 Prompt 指南提炼

模板编写参考 [OpenAI GPT-5.6 Prompt 指南](https://developers.openai.com/api/docs/guides/prompt-guidance-gpt-5p6)：

- 先描述用户可见结果，再描述成功标准、重要约束、证据和完成边界。
- 只保留会改变行为的规则，删除重复说明、无效示例和无关工具。
- 用判断条件替代不必要的“始终、绝不、只能”。
- 明确输出格式、验证方式、重试与停止条件。
- 区分回答、设计、实现和外部操作的授权边界。
- 研究类 Prompt 要定义证据、引用、冲突和证据不足时的行为。

## 信息模型

每个 Prompt 只有一个 `collection`，可以有多个 `tags`：

```swift
struct PromptMetadata: Codable, Sendable {
    var collection: PromptCollection
    var tags: [String]
    var isFavorite: Bool
    var isArchived: Bool
    var manualOrder: Int?
    var createdAt: Date
    var updatedAt: Date
    var lastUsedAt: Date?
    var useCount: Int
    var sourceURL: URL?
}
```

第一版固定主分类：

- `inbox`：新建或导入后尚未整理
- `development`：开发、调试、测试、重构、代码审查
- `research`：搜索、资料分析、带引用的研究
- `writing`：写作、总结、翻译和内容改写
- `productDesign`：产品、需求、交互和视觉设计
- `personal`：个人工作流及无法归入以上类别的模板

标签用于交叉维度，例如 `Swift`、`安全`、`前端`、`GPT-5.6`、`长任务`。来源不是分类，应单独保留为 `source` 和 `sourceURL`。

## 默认排序

使用透明、可预测的排序元组，不使用难以理解的综合分数：

1. 收藏的 Prompt 优先。
2. 用户手动排序的 Prompt 按 `manualOrder`。
3. 其余内容按 `lastUsedAt` 倒序。
4. 从未使用的内容按 `updatedAt` 倒序。

同时提供“最近使用、最近添加、名称”三种显式排序。切换分类或重新打开面板时保留用户最后选择。

## 检索与防混乱规则

- 搜索覆盖标题、正文、标签、来源和分类名称。
- 新建和导入默认进入“收件箱”，不强迫用户立即分类。
- 保存前对规范化正文计算摘要；完全重复时提示“已存在”，允许打开原条目而不是继续创建。
- 相同标题但内容不同只做弱提示，不自动合并。
- 卡片最多展示一个分类和两个标签，更多标签在详情中显示。
- 删除改为进入归档；归档页中才提供永久删除。
- 内置模板升级继续采用版本化迁移，用户删除或归档后不得被升级重新添加。

## Prompt 页面布局

```text
Prompt                         ＋ 新建
[全部] [收藏] [开发] [研究] [写作] [产品设计] [收件箱]

搜索 Prompt、标签或来源               [智能排序⌄]

模板卡片
  标题                                      ···
  两行摘要
  开发  ·  安全  GPT-5.6          OpenAI 官方
```

分类栏横向滚动；“全部、收藏、收件箱”保持固定入口。点击标签可立即追加筛选条件，搜索和分类可以同时生效。

## 新建与编辑

- 标题和正文仍为必填。
- 分类默认“收件箱”，用户可直接保存。
- 标签使用可输入的 Token Field，并提供已有标签建议。
- 来源名称和来源链接为可选字段；内置模板为只读来源。
- 使用 Prompt 与编辑模板继续保持两个独立模式，填写变量不会修改模板。

## 迁移策略

现有 `Clip` 数据保持可解码。第一阶段给 Prompt 增加可选 `PromptMetadata`；旧数据缺少元数据时：

- 内置工程模板迁移到“开发”。
- OpenAI 研究模板迁移到“研究”。
- 其他模板迁移到“收件箱”。
- 原有顺序转为 `manualOrder`，避免升级后顺序突然改变。

迁移完成后记录内容库版本，只执行一次。

## 分阶段交付

### 第一阶段

- 增加分类、标签、收藏、归档和来源链接字段。
- 增加分类筛选、动态搜索和明确排序。
- 实现完全重复检测和一次性数据迁移。

### 第二阶段

- 增加拖拽手动排序。
- 增加批量分类、批量标签和批量归档。
- 根据真实使用数据决定是否需要自定义分类，不预先支持嵌套目录。

## 验收标准

- 200 个 Prompt 下可以通过分类加搜索在两次交互内定位目标。
- 新导入 Prompt 不会污染已有分类，统一进入收件箱。
- 完全重复内容不会静默创建第二份。
- 用户的收藏、归档、排序和标签在重启后保持。
- 旧内容库升级不丢数据、不改变模板正文，也不复活用户删除的内置模板。
